# Running the gateway: key issuer steps

Generated by the `litellm-bedrock-gateway` skill for the gateway
`{{STACK}}`. Run these in a terminal, from this repository's folder. First,
every time:

```bash
source gateway.env
```

That is all a key issuer with AWS access needs (sign in first if AWS says the
session expired). Without AWS access, set up once as described in
`docs/issuer-no-aws.md`; the commands below then work the same.

The gateway URL is in `secrets/gateway-url`, never in this repository's files:
it goes to people privately, with their key.

## Workshops on the JupyterHub

A workshop gets its keys one of two ways:

- **A batch you hand to the organizer.** You make the keys ahead of time and
  send them to the workshop's organizer, who gives one to each participant.
  The organizer needs only a hub account: no clone of this repository and no
  admin key. Use this when you are not running the workshop yourself.
- **Sign-up with a code.** You open the workshop in the room and say a code;
  each participant's key is made when they type it. Use this when you (or
  someone with an issuer key) are in the room.

Either way participants run `{{HUB_COMMAND}}` and type what they were given, a
key or a code (`docs/hub-quickstart.md`). A workshop can use both.

Several workshops can run on this gateway at once. Each has a name (lowercase
letters and digits, e.g. `whale`); its keys are named `ws-<name>-...`. Every
key issuer can see and change every workshop, so agree on names with the
others.

Each workshop's settings are in `docs/workshops/<name>.md`, written when it was
planned, with the exact commands for it. To plan one:

```bash
python scripts/workshop.py plan --workshop whale --organizer jane-blow \
  --dates "14-15 Oct 2026" --people 25 --budget 20 --days 7 --batch
```

(`--batch` for a batch of keys; leave it out, and give `--hours`, for sign-up.)

**Once per hub** (and again after the script changes or the gateway URL
changes), copy the script and the URL into the hub's shared folder:

```bash
cp hub/{{HUB_COMMAND}} {{HUB_ADMIN_DIR}}/
cp secrets/gateway-url {{HUB_ADMIN_DIR}}/{{HUB_COMMAND}}.url
```

Participants run it as `{{HUB_DIR}}/{{HUB_COMMAND}}`. Use a folder
participants can read but not change.

### A batch of keys for an organizer

```bash
python scripts/keys.py batch --workshop whale --count 15 --budget 20 --days 7
```

It makes `ws-whale-01` to `ws-whale-15`, each with `--budget` US dollars,
expiring `--days` from **now** (not from first use: make the batch close to
the workshop, or add the days in between). The keys go into one file,
`secrets/whale-keys.txt`, one `<name> <key>` per line, and are not shown.
Running it again for `whale` continues at `ws-whale-16` and adds to the same
file.

Send the file to the organizer **privately**: a direct message, or copy it into
their hub home folder. Send a copy of `docs/workshop-organizer.md` (their
page) and `docs/hub-quickstart.md` (for participants) with it: they have no
copy of this repository. They can check the batch's spend from the hub;
stopping a key stays with you:

```bash
python scripts/workshop.py status --workshop whale
python scripts/keys.py block ws-whale-07
```

A key works from anywhere that has the gateway URL, not only the hub, so a
leaked key is limited by its budget and expiry until you block it. Choose
both with that in mind.

### Sign-up with a code

**When the workshop starts**, run the `open` command from its record with a
code you choose now (the code is not case-sensitive, and must differ from any
other open workshop's):

```bash
python scripts/workshop.py open --workshop whale --code whale-2026 --hours 4 \
  --budget 20 --days 7 --max 25
python scripts/workshop.py status --workshop whale
python scripts/workshop.py close --workshop whale
```

`--budget` is US dollars per key, `--days` how long each key lasts, and
`--max` the most keys the workshop hands out. Sign-up also ends by itself
after `--hours`. `status --workshop whale` lists who has a key
in that workshop, with spend, budget, expiry and whether it is blocked;
`status` alone gives one line per workshop (sign-up workshops; a batch-only
workshop shows with `--workshop`). To stop someone, block or delete their
key. If someone lost their key or took the wrong name, delete it and they
can sign up again:

```bash
python scripts/keys.py block ws-whale-their-username
python scripts/keys.py delete ws-whale-their-username
```

## Give someone a key by hand

```bash
python scripts/keys.py create someone --budget 5 --days 7
```

- `--budget` is in US dollars; `--days` is how long until it expires.
- Add `--models {{DEFAULT_MODEL}}` to limit which models it may use (default:
  all). `python scripts/keys.py models` lists them.

The key is saved to `secrets/someone.key` and not shown. Send it
**privately** (a direct message, not a shared channel or email list) together
with the gateway URL from `secrets/gateway-url` and
`docs/participant-quickstart.md`.

## Watch use and cost

```bash
python scripts/keys.py list
```

Spend appears about a minute after each request.

Or, with AWS access, the **Admin UI**: `<gateway URL>/ui`, user `admin`, with
the password from Parameter Store. It is not given to key issuers without AWS:
like the master key, it cannot be revoked.

```bash
aws ssm get-parameter --name /{{STACK}}/ui-password \
  --with-decryption --query Parameter.Value --output text
```

## Switch a key off or on, or delete it

```bash
python scripts/keys.py block someone
python scripts/keys.py unblock someone
python scripts/keys.py delete someone
```

## Installer only (needs AWS)

```bash
python scripts/keys.py issuer create maria   # admin key for a key issuer without AWS
python scripts/keys.py issuer list           # every admin and its keys
python scripts/keys.py issuer revoke maria   # stop it at once
scripts/instance.sh stop     # about $5 a month while stopped
scripts/instance.sh start
scripts/deploy.sh            # after changing models.yaml or gateway.env
scripts/teardown.sh          # deletes everything, keys and spend included
```
